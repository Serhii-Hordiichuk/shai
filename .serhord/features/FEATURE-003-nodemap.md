# FEATURE-003 · Спільна карта нод, доступна ШІ

**Статус:** 📦 ready · **Модуль:** `src/nodemap.ts` · **Клас:** `NodeMap`

## Проблема

Коли нод багато, користувач не бачить «хто є в мережі». А ШІ взагалі сліпий
до мережі — не може відповісти «з ким я з'єднаний» чи порадити зв'язок.
Потрібна **спільна, самосинхронізована карта**, яку ШІ читає і поповнює.

## Рішення

**Gossip-реєстр нод:** кожен запис — `{id (DID), alias, kind, caps, peers, firstSeen, lastSeen}`.

- **Синхронізація без сервера:** ноди обмінюються списками через
  `nodes-gossip` (FEATURE-002); злиття — за найсвіжішим `lastSeen`.
  Карта кожної ноди поступово стає однаковою — децентралізована
  конвергенція, як у чутках.
- **ШІ-доступ:** `snapshotForAi()` — текстова карта для системного промпту;
  `suggestConnections()` — пари нод зі спільними можливостями,
  ще не з'єднані, відсортовані за скором (спільні caps ×2 + спільні друзі ×3).
- **ШІ додає ноди:** коли асистент дізнається про нову ноду (з повідомлення,
  з пошуку, з інтро), він викликає `upsert()` → запис потрапляє в карту →
  наступний gossip розносить його мережею. Так «ШІ займається зв'язком»:
  знаходить ноду → реєструє → пропонує з'єднання.
- **Персист:** IndexedDB (`mesh/nodemap`) — карта переживає перезавантаження.

## API поверхня

| Метод | Що робить |
|---|---|
| `load()` / `onChange(fn)` | персист + реактивність |
| `upsert(entry)` | додати/оновити ноду (використовує і ШІ) |
| `merge(remote)` | gossip-злиття чужого списку |
| `all()` / `get(id)` / `size()` | читання |
| `snapshotForAi()` | текст карти для промпту |
| `suggestConnections(max)` | кого з ким з'єднати |

## Візуалізація (фаза 3)

Права колонка → вкладка «Map»: SVG-граф (force layout на requestAnimationFrame):
вузли — ноди (користувачі сині, ШІ-агенти фіолетові), ребра — `peers`,
імпульси біжать ребрами при gossip-оновленнях. Клік по ноді — картка:
аліас, DID, caps, «з'єднати», «попросити ШІ познайомити».
