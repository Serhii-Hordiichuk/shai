# 🔌 План інтеграції децентралізованого шару

Як чотири модулі Feature Lab (`did`, `mesh`, `nodemap`, `ai2ai`) стануть
частиною застосунку. Інтеграція — **пофазна**, кожна фаза — окремий PR і
запис у `CHANGELOG.md`.

---

## Архітектура в зборі

└───────▲─────────────────▲───────────────▲──────────────▲───────┘

## Фаза 1 — Ідентичність (FEATURE-001)

**Мета:** у кожного користувача є DID; застосунок знає, хто він.

- Boot: `did.load()` до рендеру; якщо профілю нема — модалка першого запуску.
- Store: нове поле `identity: DidProfile | null` + watcher для сайдбару.
- Settings → вкладка **Identity**: створити, аліас/колір, експорт ключа
  (AES-GCM від пароля-фрази), імпорт.
- Сайдбар: чип Guest → аліас + `short()`; кнопка «копіювати DID».
- **Критерій готовності:** створений DID переживає перезавантаження;
  підпис/перевірка проходять unit-перевіркою в консолі.

## Фаза 2 — Меш (FEATURE-002)

**Мета:** дві вкладки застосунку бачать одна одну без сервера.

- Топбар: кнопка «Nodes» (іконка `globe` з лічильником пірів).
- Панель Nodes (drawer праворуч або модалка-шторка):
  - «Створити запрошення» → код + QR (canvas, без бібліотек);
  - «Прийняти» → кроки: вставити код → скопіювати відповідь → вставити чужу відповідь;
  - Список пірів: аліас, DID, RTT, час у мережі, «від'єднати».
- Індикатор у сайдбарі: `● 3 peers`.
- **Критерій:** дві вкладки (навіть на одному комп'ютері) обмінялися
  підписаними `hello` за 30 секунд.

## Фаза 3 — Карта (FEATURE-003)

**Мета:** мережа видима; ШІ бачить і поповнює карту.

- Права колонка: перемикач **Artifacts / Map**.
- SVG-граф: force-layout на rAF, імпульси по ребрах при gossip,
  клік → картка ноди.
- `snapshotForAi()` додається до системного промпту в `ChatEngine.history()`.
- Команди: «покажи карту нод» → асистент рендерить список; ШІ може викликати
  `upsert()` через спец-дії (спершу — через підказки у відповіді).
- **Критерій:** карта з 3+ нод синхронізована між двома вкладками;
  ШІ відповідає «хто в мережі» з реальних даних.

## Фаза 4 — AI2AI (FEATURE-004)

**Мета:** ШІ самі знайомлять користувачів.

- Settings → Identity: редактор маніфеста (цікавості/моделі/мови) + тумблер згоди.
- Картки пропозицій у чаті: «Ваш агент: спільне з did:… — TypeScript, Groq.
  З'єднати?» → `introduce()`.
- Вхідні інтро — модалка підтвердження з причиною.
- Стенограма знайомства — повідомленням у розмову (як транскрипти дзвінків).
- **Критерій:** два користувачі з одним спільним інтересом отримали
  взаємні пропозиції і встановили канал після підтвердження.

## Що НЕ змінюється

- API чотирьох модулів (контракт зафіксовано в спеках).
- Поведінка застосунку без ідентичності: все працює як зараз («режим гостя»
  лишається можливим — DID створюється за бажанням).
- Edge-воркер: лишається опційним; для мешу може додати `/api/signal`
  (реле кодів запрошень) — окремий FEATURE-005, якщо з'явиться запит.

## Ризики

| Ризик | Мітигація |
|---|---|
| NAT/корпоративні мережі без P2P | Опційний signaling через воркер; зрозуміла помилка |
| Втрата ключа = втрата ідентичності | Зашифрований бекап + чесне попередження в UI |
| Спам-маніфести в мережі | Ліміт відомих агентів (100), підпис обов'язковий |
| Приватність інтересів | Згода окремо; маніфест тільки з полів користувача |
