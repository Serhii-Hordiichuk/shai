# 🧪 Feature Lab — лабораторія нових фіч

Папка для розробки великих фіч **до** їхньої інтеграції в застосунок.
Кожна фіча живе тут як окремий модуль + спека, і лише після проходження
всіх етапів потрапляє в UI.

## Життєвий цикл фічі

| Етап | Значення |
|---|---|
| 📝 **draft** | ідея, постановка проблеми, чорновий дизайн |
| 🛠 **dev** | модуль пишеться, API шліфується |
| 📦 **ready** | модуль готовий, протестований, чекає інтеграції |
| 🔌 **integrated** | під'єднано до UI/стану, фіча доступна користувачу |

**Правило:** модуль у статусі 📦 не змінює свій публічний API без запису в
[`DEVLOG.md`](./DEVLOG.md) — на ньому тримається план інтеграції.

## Ключові документи

- [`INTEGRATION-PLAN.md`](./INTEGRATION-PLAN.md) — **як і коли** все це вбудується в застосунок (фази, UI-точки, ризики)
- [`DEVLOG.md`](./DEVLOG.md) — журнал розробки: що зроблено за сесію, що далі

## Принципи

1. **Ізольованість:** модуль не імпортує UI-код і не знає про DOM (окрім WebCrypto/WebRTC).
2. **Подієвість:** спілкування через події/колбеки — інтеграція лише «обвішує» події.
3. **Без серверів за замовчуванням:** усе працює локально або P2P; Edge-воркер — лише опційне підсилення.
4. **Ключі не покидають пристрій:** приватний ключ DID живе лише в IndexedDB.
5. **Документ перший:** жодного коду без спеки в цій папці.
